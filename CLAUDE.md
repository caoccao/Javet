# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Javet (Java + V8) embeds Node.js and V8 in Java applications. One Java API (`src/main/java`, Java 8) sits on top of a JNI layer (`cpp/jni`) that is statically linked against either a V8 monolith (V8 mode) or Node.js static libraries (Node.js mode).

Versions live in a few places and are bumped by scripts, never by hand (see [Version Bumps](#version-bumps)):
- Javet: `Config.Versions.JAVET` in `build.gradle.kts`, `LIB_VERSION` in `JavetLibLoader`, `JAVET_VERSION` in `cpp/jni-build.ts`.
- Node.js / V8: the version strings in `enums/JSRuntimeType.java`, plus README, workflows and Dockerfiles.

## Repository Layout

- `src/main/java/com/caoccao/javet/` — the library.
- `src/main/resources/` — locally built native libraries (gitignored), named `libjavet-<v8|node>-<os>-<arch>[-i18n].v.<version>.<so|dylib|dll>`.
- `src/test/java/` — JUnit 5 tests.
- `cpp/` — JNI sources (`cpp/jni`), CMake (`CMakeLists.txt`, `cmake/*.cmake`, `cmake/platforms/<OS>.cmake`) and the build driver `jni-build.ts` (Deno). Build dirs `cpp/build-<v8|node>-<os>-<arch>-<i18n|non-i18n>` are gitignored.
- `android/` — separate Gradle project for the `javet-android` AAR. Its Java sources are not checked in: `scripts/python/patch_android_build.py` copies them from `src/main/java`. Native libraries go to `android/javet-android/src/main/jniLibs/<abi>/`.
- `scripts/deno/` — version bumps, the `args.gn` generator, and patches for V8, Node.js and temporal.
- `scripts/v8/gn/` — V8 `args.gn` per `<os>-<arch>-<i18n|non-i18n>`, generated by `scripts/deno/generate_args_gn.ts`. Edit the generator, not the `.gn` files.
- `scripts/v8/CLAUDE.md` — upstream V8 guide, for working inside the V8 checkout.
- `scripts/node/` — Node.js test projects and `javet-rebuild` for rebuilding native Node.js modules.
- `docker/`, `.github/workflows/` — per-platform CI builds (Linux, macOS, Windows, Android V8, Android Node.js).
- `docs/` — Sphinx docs (`sphinx-build -M html ./ ./_build`). Release notes are in `docs/release_notes/`.

The V8 and Node.js checkouts are expected as siblings: `../google/v8` and `../node`.

## Architecture

### Runtime Model

- **`JSRuntimeType`** has 4 values: `V8`, `V8I18n`, `Node`, `NodeI18n`. Each maps to its own native library and its own `V8Host` singleton: `V8Host.getInstance(type)`, `getV8Instance()`, `getV8I18nInstance()`, `getNodeInstance()`, `getNodeI18nInstance()`.
- **`V8Host`** loads the native library:
  - It goes through a per-type `JavetClassLoader`, and `JavetLibLoader` extracts the library from classpath resources. Several runtime types can therefore coexist in one JVM, and a library can be unloaded and reloaded when `V8Host.setLibraryReloadable(true)` is set.
  - It starts two daemon threads: `V8GuardDaemon` enforces `V8Guard` execution timeouts, and `V8StatisticsFutureDaemon` serves heap statistics requests.
- **`V8Runtime`** is 1 isolate + 1 context. **`NodeRuntime`** extends it with Node.js (`require()`, event loop, `node.modules`).
- **Flags**: `V8RuntimeOptions.V8_FLAGS` and `NodeRuntimeOptions.NODE_FLAGS` are sealed by native code when the library initializes, so set them before the first `V8Host` of that type is created.
- **`JavetEnginePool`** (`interop/engine`) pools runtimes; use it in production.
- **Converters** (`interop/converters`): `JavetObjectConverter` (default), `JavetPrimitiveConverter`, `JavetProxyConverter`, `JavetBridgeConverter`. Proxy handlers are in `interop/proxy`, and the annotation-driven binding (`@V8Function`, `@V8Property`, `@V8Getter`, `@V8Setter`, …) is in `interop/binding`.

### Key Packages

- `annotations` — binding annotations.
- `values` — V8 value types: `primitive`, `reference`, `reference.builtin` (wrappers for JS built-ins), `virtual`.
- `interop` — runtime, host, natives, locker/scope/guard, inspector. Subpackages: `binding`, `callback`, `converters`, `engine`, `executors`, `loader`, `monitoring`, `options`, `proxy`.
- `interception` — console, JVM and logging interceptors.
- `exceptions` — `JavetException` and `JavetError`.
- `enums`, `entities`, `interfaces`, `utils`, `node.modules`.

### JNI Boundary

- **Java side**: `IV8Native` / `INodeNative` are the interfaces. Package-private `V8Native` / `NodeNative extends V8Native` declare the `native` methods. Keep those classes free of references to other types, and keep methods in ascending alphabetical order so the generated headers stay stable.
- **Headers**: `./gradlew buildJNIHeaders` runs `javac -h` and regenerates `cpp/jni/com_caoccao_javet_interop_{V8,Node}Native.h`.
- **C++ implementations** live in:
  - `cpp/jni/javet_jni_<area>.cpp` (object, string, function, module, …)
  - `javet_jni_core_{v8,node}.cpp`
  - `javet_v8_runtime.*`, `javet_converter.*`, `javet_callbacks.*`
- **Exports**: symbols matching `Java_com_caoccao_javet_*` are exported through `exported_symbols_list.txt` (macOS) and `version_script.map` (Linux).
- **Duplicated enums**: `cpp/jni/javet_enums.h` mirrors enums in `com.caoccao.javet.enums` (`V8ValueType`, `V8ValueInternalType`, `V8ValueErrorType`, `V8ContextType`, …). Change both sides together.
- **V8 internals**: `cpp/jni/javet_v8_internal.h` includes V8 internal headers (`src/objects/*-inl.h`, `src/api/api-inl.h`, …), so V8 upgrades often break the JNI build.
  - The include dirs in `cpp/cmake/JavetV8.cmake` and `JavetNode.cmake` must mirror the public `include_dirs` of V8's GN configs (e.g. `third_party/simdutf`, `third_party/fp16/src/include`, `third_party/abseil-cpp`).
  - Defines such as `V8_ENABLE_WEBASSEMBLY`, `V8_ENABLE_LEAPTIERING`, `V8_TEMPORAL_SUPPORT` and `V8_INTL_SUPPORT` must match the engine build, or the Torque-generated layouts diverge.

## Common Commands

### Java

```bash
./gradlew build                 # compile, test, jar, sources/javadoc jars
./gradlew test                  # tests excluding @Tag("performance")
./gradlew performanceTest       # performance tests only
./gradlew test --tests "com.caoccao.javet.exceptions.TestJavetError"
./gradlew test --tests "com.caoccao.javet.exceptions.TestJavetError.testErrorType"
./gradlew buildJNIHeaders       # regenerate JNI headers into cpp/jni
```

### Native JNI Library

Run the build from `cpp/`; it requires Deno and CMake:

```bash
deno run build --os <linux|macos|windows|android> --arch <x86_64|arm64|arm|x86> \
  (--v8-dir <path> | --node-dir <path>) [--i18n] [--clean] [--cpu-count <n>] \
  [--android-ndk <path>] [--log-debug] [--log-error] [--log-info] [--log-trace]
```

- The output is copied to `src/main/resources/`, or to `android/javet-android/src/main/jniLibs/<abi>/` for Android.
- **V8 prerequisites**:
  - A static `v8_monolith` built with `scripts/v8/gn/<os>-<arch>-<i18n|non-i18n>-args.gn` into `<v8-dir>/out.gn.<os>.<i18n|non-i18n>/<x64|arm64|ia32|arm>.release`.
  - `libtemporal_capi.a` copied into that `obj/` directory. Build it from `boa-dev/temporal` after patching with `scripts/deno/patch_v8_temporal.ts`.
- **Node.js prerequisites**:
  - Static libraries in `<node-dir>/out.<i18n|non-i18n>/Release` (Android: `out.<arch>.<i18n|non-i18n>/Release`).
  - Patch the Node.js tree first with `scripts/deno/patch_node_build.ts -p <node-dir> --os <os> [--i18n]`.
- Full per-platform steps are in `docs/development/build_javet_from_scratch.rst`.

### Version Bumps

Edit the version literal in `main()` of the script, then run it from `scripts/deno/`:

```bash
deno run --allow-all change_javet_version.ts     # Javet version across Gradle, README, docs, CI, Docker, cpp, Android
deno run --allow-all change_node_v8_version.ts   # Node.js and V8 versions
deno run --allow-all generate_args_gn.ts         # regenerate scripts/v8/gn/*.gn
```

## Testing

- **Runtime selection**: `BaseTestJavet` picks the `JSRuntimeType` whose library in `src/main/resources` has the newest mtime.
  - To switch modes, `touch` the library you want (see `scripts/shell/build_javet_artifacts.sh`), or pass an explicit `JSRuntimeType` to the `BaseTestJavet` constructor.
  - Tests only run if a native library for the current platform is in `src/main/resources`.
- **Flags and ICU data**: `BaseTestJavet` sets the test flags (`allowNativesSyntax`, `useStrict`, heap limits, …). For i18n builds it also points ICU data at `../google/v8/third_party/icu/common/icudtl.dat` and `../node/deps/icu-tmp`.
- **Leak checks**: `BaseTestJavetRuntime` creates a fresh `v8Runtime` per test. After each test it asserts:
  - the callback context count is 0,
  - the reference count equals the module count,
  - the native internal-statistic counters are balanced.

  A V8 value left unclosed therefore fails the test.
- **Pool tests**: `BaseTestJavetPool` is the base for engine-pool tests.

## Conventions

- **Java 8 language level**, and the code must also work on Android.
  - Wrap JVM-only code in `/* if not defined ANDROID */ … /* end if */`; `patch_android_build.py` turns that block into a comment.
  - Put Android-only code inside `/* if defined ANDROID … /* end if */`; the script activates it by closing the comment.
  - The script also comments out a fixed list of imports (`javax.management.*`, `java.lang.management.*`) and rewrites `.getParameterCount()` for Android.
- **Javadoc**: every public type and member gets Javadoc with `@since <version>`.
- **License header**: every source file starts with the Apache 2.0 header `Copyright (c) 2021-2026. caoccao.com Sam Cao`.
- **Closing V8 values**: `V8Value`, `V8Runtime` and engines implement `IJavetClosable`. Use try-with-resources, and never leak references in tests (see [Testing](#testing)).
- **Commit subjects**: use an emoji plus a conventional type, e.g. `🐛 fix: …`, `🐳 chore: …`, `🦄 refactor: …`, `📃 docs: …`.
